# Audit Data Transformer — Конструктор расшифровок

Локальный прототип преобразования нестандартных бухгалтерских XLSX-выгрузок в стандартизированные плоские таблицы. Интерфейс следует дизайн-системе EMP, но проект не имеет runtime-зависимости от EMP.

## Возможности

- безопасный вход по email/паролю и серверные сессии в `HttpOnly` cookie;
- роли `USER` и `ADMIN`;
- загрузка и реальная обработка XLSX;
- ОСВ и журнал проводок;
- полный profiler книги, детерминированный parser и контроль результата;
- локальный LLM Planner через Ollama и `max-gpu-qwen:latest`;
- повторная обработка по замечанию с сохранением предыдущей версии;
- preview первых 100 строк и защищённое скачивание XLSX;
- история преобразований;
- административный журнал действий;
- четыре синтетических XLSX-набора с ожидаемыми результатами.

## Требования

- Node.js 22+ и npm 10+;
- Python 3.12+;
- Ollama на `http://127.0.0.1:11434`;
- модель `max-gpu-qwen:latest`.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm install
npm install --prefix frontend
cp .env.example .env
```

Перед использованием вне локального прототипа замените `APP_SECRET` и демонстрационные пароли в `.env`.

## Подготовка данных

```bash
npm run seed
npm run generate:fixtures
```

Синтетические файлы создаются в `test-data/generated`. Они не содержат клиентской информации.

## Запуск

```bash
npm run dev
```

- Web: `http://localhost:5174`
- API: `http://127.0.0.1:8000`
- Swagger: `http://127.0.0.1:8000/docs`
- Health и состояние Ollama: `http://127.0.0.1:8000/health`

## Демонстрационные учётные записи

При стандартном `.env.example`:

| Роль | Email | Пароль |
| --- | --- | --- |
| Пользователь | `user@transformer.local` | `ChangeMe123!` |
| Администратор | `admin@transformer.local` | `ChangeAdmin123!` |

Пароли сохраняются в SQLite только в виде Argon2id-хешей.

## Как работает LLM

Сначала `RulePlanner` строит базовую спецификацию по всей книге. Локальная Qwen получает структурный профиль и базовую спецификацию, после чего возвращает только JSON по строгой Pydantic-схеме. Спецификация проверяется по существующим листам, диапазонам и колонкам. Код от LLM не принимается и не исполняется.

Первичная обработка может продолжиться по детерминированным правилам, если Ollama временно недоступна. Повторная обработка по текстовому замечанию требует доступной LLM и иначе возвращает `LLM_UNAVAILABLE`.

## Ограничения прототипа

- поддерживается только `.xlsx`, без PDF, OCR и макросов;
- формулы не вычисляются на backend — используются сохранённые Excel-значения;
- очередь задач выполняется внутри одного процесса FastAPI;
- файлы и SQLite хранятся локально в ignored-каталоге `data/`;
- сложные неоднозначные структуры могут потребовать пользовательского замечания;
- LLM-анализ большой книги может занимать заметное время, при этом UI показывает реальный этап обработки.
